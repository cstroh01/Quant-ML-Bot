# Quant-ML-Bot — project audit

Audit date: September 12, 2026. Workspace: `C:\GitHub\Quant-ML-Bot`.

**Verdict: a substantial research prototype, with useful foundations, but neither a production trading system nor evidence of a profitable strategy.** The next milestone should be a trustworthy, funded, reproducible experiment. A more sophisticated model cannot repair a mismatched prediction target, incomplete accounting, or invented dashboard evidence.

This report distinguishes **D: demonstrated defect**, **G: missing capability/evidence**, and **R: design choice to reconsider**. P0 means block capital deployment or reliance on the affected result; P1 means address before treating research as investment evidence or operating a reliable paper system; P2 means engineering/product improvement. These priorities do not imply that every unfinished production capability violates the deliberately narrower historical spec.

The review covered the application Python, tests, API, React/TypeScript/CSS, all available specs 001–017 and their plans/tasks/contracts/research, project instructions, ADR, CI, agent instructions, shell/PowerShell tooling, templates, configuration, and image assets. The inventory is a scope record, not a claim that reading code proves it correct or that no further defects exist. Undocumented decisions, private strategy code, remote branch protection, broker accounts, external instruction files not present in this workspace, and real execution behavior cannot be established from these files. **Fix register: accounting, execution, and capital safety**

**01 — P0 / G+D: replace the one-share P&L harness as the source of account returns.** [backtest_harness.py](../../scripts/backtest_harness.py:13), [metrics.py](../../scripts/metrics.py:63). The harness has no cash, buying-power, quantity, or portfolio ledger. A probe with $100 starting capital accepts an entry requiring $201.10. A one-share trade-price difference is a valid research primitive, but dividing its cumulative P&L by the first close does not make it an investable account. Add explicit starting cash, filled quantities, cash reservations, positions, fees, corporate actions, financing if allowed, and mark-to-market equity. Reject or resize unaffordable orders. Acceptance: cash + marked positions reconciles on every event; no unauthorized borrowing; a split and a dividend reconcile by hand.

**02 — P0 / D: include initial capital before the first fill in return and drawdown calculations.** [metrics.py](../../scripts/metrics.py:176), [metrics.py](../../scripts/metrics.py:226). A $100 account with $5 entry and exit commissions yields recorded equities `[95,95,90]`. Current drawdown is −5.263%; actual drawdown from starting capital is −10%. The first return is omitted too. Anchor the metric series to pre-trade equity while retaining unambiguous timestamps. Acceptance: first-bar loss, first-bar profit, all-flat, and terminal loss match an independent cash ledger.

**03 — P0 / D: reject invalid fills instead of summarizing them as harmless results.** [backtest_harness.py](../../scripts/backtest_harness.py:13), [backtest_harness.py](../../scripts/backtest_harness.py:108). An NaN opening fill produces NaN trade P&L, while aggregation reports one trade and zero total P&L. Validate finite positive prices, finite costs, and exact boolean signal types before simulation; reject missing fill prices or apply a documented unavailable-market policy. Never use missing-value-skipping sums as proof of reconciliation. Acceptance: corrupt input fails explicitly and cannot receive a successful tearsheet.

**04 — P0 / D: enforce cost domains consistently at every public entry point.** [ml_signal.py](../../scripts/ml_signal.py:47), [backtest_harness.py](../../scripts/backtest_harness.py:13), [backtest route](../../reports/api/routes/backtest.py). Negative comparisons do not reject NaN or infinity. API requests accept `commission=nan` and `slippage_bps=10000`; the latter can create zero/negative effective sale prices. Centralize finite nonnegative commission, finite slippage in `[0,10000)`, supported quantities and valid thresholds. Test both library and HTTP boundaries. Research zero-cost controls may remain explicit; production runs must carry an explicit cost configuration.

**05 — P0 / G: wire portfolio sizing and risk into the actual execution/accounting path.** [portfolio_risk.py](../../scripts/portfolio_risk.py:482), [multi_ticker_comparison.py](../../scripts/multi_ticker_comparison.py:212). Spec 017 intentionally stops at target weights. Current costed backtests do not demonstrate that those weights, changing equity, commissions, share rounding, halts, and fills work together. Add a portfolio runner and order-sizing adapter; retain the risk module as a pure decision component. Acceptance: end-to-end replay shows a drawdown triggering the guard, prohibiting new/increased exposure, permitting reductions, and charging all resulting trades.

**06 — P0 / G: persist risk state and reconcile it before resuming after a restart.** [portfolio_risk.py](../../scripts/portfolio_risk.py:611). A weekly halt disappears when a fresh `LossCapGuard` is created: reproduced `True → False` at the same depressed equity. In-memory state is appropriate for the current isolated module, insufficient for live operation. Persist anchors, high-water marks, latch reasons, last observation and configuration; restore through deterministic event replay. Treat deposits/withdrawals separately from trading P&L. Acceptance: crash at every state transition and restart without relaxing limits.

**07 — P0 / G: distinguish loss triggers from guaranteed loss limits.** [portfolio_risk.py](../../scripts/portfolio_risk.py:611), [capital gate](../../reports/api/routes/capital_gate.py). Daily closing observations cannot prevent overnight gaps, intraday losses, failed exits or a loss exceeding a threshold. Define halt-new-orders, cancel-open-orders and reduce/flatten as separate policies with failure behavior. Add stale-data/broker-disconnect/buying-power checks and an account-level emergency stop. Decide explicitly whether an all-time drawdown latch and operator reset are needed; calendar-week reset is not itself capital protection.

**08 — P0 / G: build an order lifecycle and recovery protocol before broker connectivity becomes live execution.** No broker/OMS adapter currently implements client order IDs, acknowledged/rejected/partial/cancelled states, timeout-after-submit reconciliation, duplicate-event handling, or broker-versus-local position checks. Use durable intent IDs and reconcile uncertain outcomes before retrying; never treat a network timeout as proof no order exists. Acceptance: replay partial fills, reordered/duplicate events, disconnect after accepted submission, and restart with outstanding orders. Official [Alpaca order documentation](https://docs.alpaca.markets/us/docs/orders-at-alpaca) is an example lifecycle contract, not a recommendation to choose that broker without checking your requirements.

**09 — P1 / G: make costs and fills realistic for the selected deployment.** Fixed $1 commissions and 5 bps slippage are reproducible assumptions, not a calibrated execution model. Include bid/ask spread, session/opening-auction behavior, order size, minimum commissions, partial fills, liquidity/participation caps and applicable fees; financing/borrow only if those activities are enabled. Preserve a simple model for unit tests. Acceptance: compare base and adverse cost scenarios, report break-even cost, and eventually calibrate from actual observed execution. A zero-commission broker still has execution costs.

**10 — P1 / D+R: separate final marking from simulated liquidation and live decisions.** [backtest_harness.py](../../scripts/backtest_harness.py:13), [ml_signal.py](../../scripts/ml_signal.py:160). Open positions are closed at the dataset's final close, while the signal layer forces its last desired position flat. The end of a downloaded array is not a market event; adding another row changes that formerly last decision. Separate open-position valuation, optional benchmark liquidation, and real exit orders. The streaming signal function must not flatten merely because it received a finite batch. Record liquidation assumptions in metrics.

**11 — P1 / G: strengthen ledger validation beyond one aggregate P&L equality.** [metrics.py](../../scripts/metrics.py:63). Total reconciliation can miss invalid chronology, overlapping positions, reversed dates, missing rows or wrong metadata. Validate unique ordered sessions, permitted position transitions, trade/fill IDs, quantities, fee attribution and per-event balances. Protect zero/negative equity behavior explicitly: log returns and conventional drawdown statistics cease to behave normally at insolvency.

**12 — P1 / R: align Sharpe, compounding and cash economics.** [metrics.py](../../scripts/metrics.py:195), [return_stats.py](../../scripts/return_stats.py:35), [constants.py](../../scripts/constants.py). The code reports a log-return-based Sharpe with a fixed annual risk-free assumption. State the convention, use consistent period units, distinguish annualized mean log return from CAGR, and model cash interest separately from the benchmark hurdle. Use historical rates or explicitly label a constant assumption. Report autocorrelation-aware uncertainty; `sqrt(252)` is not automatically justified for compressed or irregular observations.

**Fix register: targets, ML, validation and statistics**

**22 — P0 / D+R: predict the return the strategy can actually capture.** [targets.py](../../scripts/targets.py:88), [ml_signal.py](../../scripts/ml_signal.py:75). The label is `log(Close[t+h]/Close[t])`; decisions after close trade at the next open. For h=1, overnight movement included in the target can occur before entry. The cost hurdle is derived for open-to-open execution. Define `feature_available_at`, `decision_at`, `entry_at`, `exit_at`, and `label_available_at` together. For next-open entry and h-session holding, a possible target is `log(Open[t+h+1]/Open[t+1])`; its label availability and purge horizon must change accordingly. Validate with a synthetic overnight-only move that the model cannot claim pre-entry profit.

**23 — P0 / D: decouple feature computation from label availability and preserve the execution calendar.** [features.py](../../scripts/features.py:106). `build_features` removes rows lacking `Label` and resets the index. This removes the freshest inference rows and compresses time when features/labels are missing. In the API, September 4 raw data becomes a September 3 ML rundown. Implement causal features on all sessions, a separate training mask for known labels, and OOS predictions aligned by ticker/session. Shift decisions on the original trading calendar; missing features must not change what “next open” means.

**24 — P1 / D: missing current prices must not become valid down labels.** [targets.py](../../scripts/targets.py:65). `NaN <future comparison>` becomes false and is cast to class 0; reproduced with `[NaN,101,102]`. Mask both current and future observations, reject nonfinite/invalid positive-price inputs, and keep genuinely unavailable labels missing. Add explicit tests for NaN/infinity at both endpoints.

**25 — P1 / R: define the prediction-to-utility contract.** [ml_signal.py](../../scripts/ml_signal.py:125), [model_cv.py](../../scripts/model_cv.py:193). A predicted expected log return compared with a log break-even hurdle is not automatically expected positive dollar profit; `exp(E[log return])` differs from `E[simple return]`. Classification accuracy likewise ignores win/loss magnitudes. Estimate an actionable conditional payoff or payoff distribution, include uncertainty and costs, and select the trade policy inside training/validation only. Keep MSE/log loss as diagnostics. A correct hurdle derivation cannot rescue the wrong economic estimand.

**26 — P1 / G: do not describe the classification path as cost-aware.** [ml_signal.py](../../scripts/ml_signal.py:236). It holds on hard class 1 and has no magnitude or cost threshold. That limitation is documented in the function but obscured by broader architecture descriptions. Preserve class probabilities, calibrate chronologically and combine them with conditional up/down payoffs, or retain classification solely as a benchmark. A 54% up probability is not interchangeable with confidence suitable for portfolio sizing.

**27 — P1 / G: create an untouched final evaluation and an experiment ledger.** [feature_set_comparison.py](../../scripts/feature_set_comparison.py:745), [project context](../PROJECT_CONTEXT.md). The same historical results have guided features, model families, windows and policy decisions. Repeated outer-test inspection turns that history into research/selection data. Register every material trial, including failed variants and manual changes; freeze the strategy before a genuinely untouched chronological evaluation. Already-inspected dates cannot be made unseen by renaming them. New forward observations may be the only honest final holdout.

**28 — P1 / G: replace per-row independence assumptions with time-aware inference.** [feature_set_comparison.py](../../scripts/feature_set_comparison.py:348), [feature_set_comparison.py](../../scripts/feature_set_comparison.py:410). Adjacent prediction errors share market regimes and fitted models; h>1 labels overlap directly. Plain paired tests do not account for that dependence, and signed-rank tests have symmetry assumptions beyond “nonparametric.” Use paired block bootstrap/appropriate dependent-data tests, date-block resampling across a multi-asset panel, confidence intervals and effect sizes. Validate the proposed inference on simulated nulls. [SciPy's Wilcoxon assumptions](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wilcoxon.html).

**29 — P1 / D: fix the unfavorable one-sided exact McNemar tail.** [feature_set_comparison.py](../../scripts/feature_set_comparison.py:348). Converting two-sided p to `1-p/2` in the unfavorable direction drops the discrete observed mass. A probe with zero favorable discordances out of two reports 0.75; the exact one-sided binomial result is 1.0. Call the exact binomial test with the intended alternative directly and cover both directions and ties. The saved favorable logistic result is not invalidated by this particular branch bug; its inferential limitations are separate.

**30 — P1 / G: adjust selection claims for the full search, not one screen.** Four tests with a rule that any p<0.10 passes are not a 10% family-wide test, and the true research search is larger than those four entries. Specify the family and correction in advance. Calculate PSR/DSR on valid net strategy returns, accounting for the search history and uncertainty in effective independent trials. “Deflated Sharpe remains positive” in [capital_gate.py](../../reports/api/routes/capital_gate.py) is not a meaningful pass rule: the usual DSR is a probability, so merely being above zero is almost vacuous. Define a justified probability threshold, minimum sample and economic effect, not a badge. [Bailey and López de Prado's original DSR paper](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf).

**31 — P1 / G: evaluate every strategy and baseline on an identical investable interval.** [multi_ticker_comparison.py](../../scripts/multi_ticker_comparison.py:212). Current ML remains flat during initial training while baselines are evaluated over the full feature frame. That is a defensible deploy-from-day-one cash policy only if explicitly intended; it is not a clean comparison of the OOS trading rules. Precompute features with prior history, then start all funded portfolios on the same evaluation session with the same cash, tradability and cost rules. Save the exact covered-session mask.

**32 — P1 / G: strengthen baselines and retain their distributions.** [ma_crossover_backtest.py](../../scripts/ma_crossover_backtest.py:59), [multi_ticker_comparison.py](../../scripts/multi_ticker_comparison.py:112). Include always-up/rolling-prior classification, zero-return and training-mean regression, cash, buy-and-hold, simple momentum and volatility-managed market exposure as appropriate. Compare turnover and exposure, retain every random path, and use uncertainty rather than “mean plus two standard deviations” as a universal threshold. Do not average Sharpe or drawdown into a fictional representative strategy.

**33 — P1 / D+G: make comparison artifacts complete and machine-actionable.** [multi_ticker_comparison.py](../../scripts/multi_ticker_comparison.py:112), [multi_ticker_comparison.py](../../scripts/multi_ticker_comparison.py:357). **34 — P1 / R: disentangle feature redesign from preprocessing changes.** [estimators.py](../../scripts/estimators.py:203), [feature_set_comparison.py](../../scripts/feature_set_comparison.py:129), [logistic_baseline.py](../../scripts/logistic_baseline.py). **35 — P1 / D: singular-matrix VIF must not report reassurance.** [feature_diagnostics.py](../../scripts/feature_diagnostics.py:76), [scratch duplicate](../../scripts/scratch_multiticker_collinearity.py:112). The diagonal of a pseudoinverse correlation matrix is not valid VIF for singular predictors. Two identical columns return VIF 0.25 each; perfect collinearity should be identified as infinite/undefined. Constant columns also produce SVD failure. Detect zero variance and rank deficiency, or regress each feature on the others with an explicit degeneracy policy. Acceptance: exact duplicate, linear combination, constant and nearly singular examples match an independent oracle.

**36 — P1 / R: good conditioning is a numerical property, not an alpha certificate.** [features.py](../../scripts/features.py), [spec 014](../../.specify/specs/014-scale-free-features/spec.md), [FeatureDiagnosticsView](../../reports/web/src/components/views/FeatureDiagnosticsView.tsx). Scale-free ratios are sensible and fold-local scaling should remain. They do not guarantee stationarity, bounded future support, causal relevance or profitability. Low pairwise correlation does not rule out multivariate redundancy; trees and ridge respond differently to correlation. Treat diagnostics as diagnostics. Only predeclared OOS economic ablation can support a strategy improvement claim.

**37 — P2 / R: reconsider permanent post-test embargo exclusions in strictly forward CV.** [walk_forward_cv.py](../../scripts/walk_forward_cv.py:21). The implementation intentionally accumulates every old post-test embargo gap forever. In past-only expanding training this is conservative data removal, not evidence of a current leak; the justification differs from embargo in CV that includes future training observations. HGB automatic early stopping can introduce an internal nonchronological validation subset once its sample threshold is crossed; the current single-ticker data is below that threshold. Specify early-stopping behavior for a future pooled panel. Handle single-class folds explicitly for each estimator. The audit checked the all-positive HGB case and did not find a material probability defect; do not add a speculative bug to the backlog. Freeze or defensively copy mutable registry dictionaries if configurations become externally editable.

**Fix register: portfolio design**

**40 — P1 / R: replace binary-active overlap penalties with exposure-sensitive portfolio risk.** [portfolio_risk.py](../../scripts/portfolio_risk.py:360). A weight of `1e-12` in a perfectly correlated second asset halves the first asset's weight from 25% to 12.5%, just as a large position would. The active-name count creates a discontinuity unrelated to dollar risk. Use a regularized covariance matrix, portfolio variance `w'Σw`, marginal risk contributions, and sector/factor limits; or compare a clearly specified weighted-overlap alternative. Acceptance: tiny exposures have tiny effects, limits behave continuously, and realized risk/turnover remain acceptable out of sample.

**41 — P1 / R: distinguish per-asset inverse-vol sizing from portfolio volatility targeting.** [portfolio_risk.py](../../scripts/portfolio_risk.py:306). `confidence × target_vol / asset_vol` does not target total portfolio volatility. The documented full-conviction diagnostic produces median gross exposure around 0.38 after the overlap penalty and removes median 69% of pre-adjustment exposure. That may be conservative by choice, but it is not automatically optimal or “10% portfolio vol.” Compare risk-normalized allocations, cash returns and turnover. Shrinkage is available in the existing dependency stack: [scikit-learn Ledoit-Wolf](https://scikit-learn.org/stable/modules/generated/sklearn.covariance.ledoit_wolf.html).

**42 — P1 / G: define and calibrate conviction before using it as a weight multiplier.** [portfolio_risk.py](../../scripts/portfolio_risk.py:306), [spec 017 research](../../.specify/specs/017-position-sizing-risk/research.md). A `[0,1]` input domain is not a definition of economic confidence. Specify whether it is calibrated win probability, normalized expected utility, uncertainty-adjusted edge or an abstention score. A toy Kelly formula based on accuracy assumes particular payoff magnitudes and is not a general sizing equation. Keeping Kelly out now is sensible; eventually estimate payoff distribution and estimation error before revisiting it.

**43 — P1 / G: enforce halt and risk limits on executable quantities.** [portfolio_risk.py](../../scripts/portfolio_risk.py:445). Clamping target weights to current weights at close does not necessarily prevent increased shares at the next open after a price gap or equity change. Convert targets through a broker-aware sizing layer and enforce no-add against actual/reserved quantities as appropriate. Include pending orders in exposure. Validate lot sizes, fractional-share support, price bands and cash reserves.

**44 — P2 / R: validate risk assumptions instead of treating defaults as optimal.** [portfolio_risk.py](../../scripts/portfolio_risk.py:167). Volatility/correlation windows, cap ordering and weekly reset are plausible policy choices. Compare a small preregistered set under stressed correlation, gaps, volatility jumps and turnover costs. Public correlation helpers should reject materially asymmetric or otherwise invalid matrices, or document their stricter upstream contract. Threshold-triggered derisking can sell after losses and repurchase after recovery; measure that behavior instead of assuming the guard improves returns.

**Design decisions worth preserving**

The project already separates signals from fills, makes purge/horizon parameters explicit, uses chronological outer evaluation with training-only inner tuning, keeps linear preprocessing inside fitted pipelines, seeds stochastic controls, derives the transaction hurdle carefully, and writes adversarial risk tests. These are useful foundations. The new risk module validates many boundary inputs substantially better than the older harness/API. Avoid discarding this work in a wholesale rewrite. Preserve its good interfaces while replacing the accounting and experiment contracts beneath misleading claims. Training-only preprocessing follows the [scikit-learn leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html); it is necessary but does not establish the correctness of the surrounding data timeline.

**Highest-value research and innovation directions**

**A. Build an execution-aligned, uncertainty-aware decision policy.** This is the highest-value quant/ML extension after the ledger and timing fixes. Predict the distribution of a return over a tradable interval, then decide whether expected gain exceeds costs, risk and uncertainty. Start with a calibrated simple baseline and a small quantile/distributional tree model; do not begin with a transformer. Compare against the current mean-return threshold with identical folds and funded-account rules.

For a long-only book, a useful research objective is:

`maximize_w   μ'w − (λ/2) w'Σw − transaction_cost(w − w_previous)`

subject to cash, name/sector/factor exposure, turnover, liquidity and halt constraints. Here μ must represent the actionable expected payoff, Σ an appropriately estimated return covariance, and transaction costs must use actual notional/quantity. A conservative uncertainty penalty can reduce μ; this is a design hypothesis to validate, not a guaranteed statistical bound. Test a no-trade region and asymmetric entry/exit policy inside the inner training process. Measure net expectancy, downside, calibration, participation and stability; let the policy abstain when evidence is weak.

Differentiation would come from correctly linking uncertainty and execution to allocation, with a traceable reason for every trade. It would not come from calling a hardcoded percentage “confidence.”

**B. Research a narrow, point-in-time cross-sectional hypothesis with an economic mechanism.** The current five correlated securities and a few moving-average/volume features do not establish a defensible information advantage. Choose one hypothesis with a reason returns might be predictable after costs—such as relative trend/reversal conditional on volatility and liquidity—across a predefined, sufficiently broad tradable panel. Residualize or benchmark market/sector exposure so a favorable beta regime is not sold as alpha. Split by global date, not random stock rows; keep future dates for every stock out of training.

Only after that works should you add costly external data. Your engineering background could help formulate specific energy/materials supply-chain hypotheses using legally available, timestamped releases. Archive publication and first-availability times, revisions and acquisition costs. A text model can extract structured events with source passages and uncertainty; its value must survive ablation against simpler price-only and calendar baselines. Research hypothesis, timestamped dataset and evidence of incremental net value are the potential differentiators—not the model brand. None of these ideas can presently be certified unique or profitable.

**C. Integrate covariance-aware risk with turnover-aware execution.** Compare the existing overlap rule against shrinkage covariance scaling plus explicit sector/factor constraints. Add a no-trade band so small forecast/covariance changes do not constantly rebalance. Decompose risk and P&L by asset, factor, prediction, costs and cash. Test confidence calibration independently from risk estimation. Start with long-only, no leverage; only expand constraints if evidence requires it.

The decisive experiment is not whether the new allocation looks more sophisticated. It is whether it improves a preregistered net objective at comparable risk and remains robust under doubled modeled costs, correlation shocks and modest parameter changes. Record failure as a valid outcome.

**D. Make the research-to-paper pipeline replayable and auditable.** This is the strongest software/product opportunity. Each displayed decision should resolve to immutable data, features, model/fold, predicted payoff, constraints, order intent and fills. The same decision/risk code should consume historical events and paper/live events through different adapters. Use durable journals and reconciliation; acknowledge that simulations and brokers cannot promise universal exactly-once delivery.

A minimal architecture is sufficient: immutable raw snapshots → causal features and known-label masks → experiment runner → versioned approved model/policy → target portfolio → order intents and broker adapter → fill/cash/risk journal → read-only API/UI. Keep offline fitting out of HTTP requests. Begin with local artifact files and a transactional state store suited to one operator; add services only for actual operational boundaries.

Automate a recurring research report after each completed run: validate dataset/folds, compare baselines, summarize uncertainty and costs, check artifact provenance, and publish a local evidence bundle consumed by the UI. This directly replaces the current manual copying of numbers and stale gate badges. A future paper-versus-simulation report should attribute differences to data, timing, signal, sizing and fills. Broker paper simulation omits some real-market effects, so successful paper operation is an operational gate rather than proof of live alpha. [Alpaca's documented paper limitations](https://docs.alpaca.markets/us/docs/paper-trading).
