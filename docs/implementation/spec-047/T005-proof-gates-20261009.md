## Findings and fixes

**P1-a: the helper accepted framework errors as proof.**

The old `failures()` discarded `spawnSync`'s exit status. It also pushed a failed suite's message
into the same list as assertion failures.

- Reproduced against the old bytes (Node 22.22.0, Vitest 5.0.3, this fix's fixtures):
  - `control(hook)` passed: every assertion passes, then the `afterAll` hook throws.
  - `control(unhandled)` passed: the assertion passes, then a promise rejection is left unhandled.
- New design:
  - `runConfig` records the exit status, any spawn error and the console text.
  - `summarize` separates named assertion failures from runner errors. A runner error is any of:
    - a suite message
    - a failed file with no failed assertion
    - "Unhandled Errors/Rejections" in the output
    - a missing report
    - a spawn error
    - zero collected tests
    - exit 0 with failures
    - a nonzero exit with no failure
  - `classify` returns `error` whenever a runner error exists. An error is never a kill.
  - `control` requires exit 0, at least one collected test, no failures and no runner errors.

**P1-b: the CI red proof accepted any nonzero exit.**

The inverted `if` is replaced by `npx vitest run mutation/redproof.test.ts`. That test calls
`plantedRed`, which passes only when all of these hold:

- the exit is nonzero
- the JSON report parses
- exactly one failure is present: the collected test named `planted failure`, with message
  witness `T005 PLANTED`
- there are no runner errors
